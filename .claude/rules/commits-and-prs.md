# Commits, PRs and releases

Applies to every change. Contributor workflow for parallel agent sessions: `docs/contributing/agent-workflow.md`;
labels and the roadmap project: `docs/contributing/issues-and-project.md`.

## Conventional Commits

- Format: `<type>(<scope>): <summary>`. After the squash the PR title **is** the commit title on `main`, so the PR title
  must be Conventional too — the CI job `pr-title` enforces it.
- Types: `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.
- Scope: area/crate — `model`, `engine`, `podman`, `ingress`, `api`, `daemon`, `cli`, `ci`, `docs` (omit when the change
  is repo-wide).
- Breaking change: `feat(model)!: ...` and `BREAKING CHANGE:` in the description; describe rollback/compatibility in
  the PR as well.
- Examples: `feat(engine): provision apps without starting them`, `fix(podman): map libpod 500 to NotFound`,
  `docs: index the ADRs`. Old commits (before 2026-10-24) are not Conventional — history is not rewritten.
- Commits, PR titles and PR bodies are in English; `Closes #NN`; reference issues (`#NN`), never private notes.

## Releases (release-plz, ADR 0015)

- Changelogs and versions are **per crate**, generated by release-plz from PR titles. Which crates a change affects is
  decided by the changed files, not by the scope. Crate versions are bumped by the release PR, never by hand-editing
  `version` or `CHANGELOG.md`.
- Internal dependencies in `[workspace.dependencies]` carry `version = "0.0"` (ADR 0015, addendum) — do not write the
  current version there, or release-plz will bump every dependent together with the crate that changed.
  Exception: `weglarka-api` (the CLI↔daemon contract) has an exact version, so releasing it also releases
  `weglarka-cli` and `weglarka-daemon`.
- The tag `vX.Y.Z` is the `weglarka-daemon` version (it triggers `release.yml`).

## Before a PR (checklist)

1. `git fetch origin && git rebase origin/main` — the PR must be on the current `main`, otherwise GitHub shows a
   conflict and does not run CI. In an agent session `git rebase --continue` waits for an editor, so call it as
   `GIT_EDITOR=true GIT_SEQUENCE_EDITOR=true git rebase --continue`; after the rebase run `scripts/adr.sh lint` (an ADR
   number or a section link may have collided with upstream — see item 5).
2. `cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`.
3. Snapshots: `INSTA_UPDATE=always cargo test`, review the `.snap` diff and commit the `.snap` files (`.snap.new` is
   ignored).
4. New `AppSpec`/`ContainerSpec` field: optional, outside `spec_hash` when unset (`skip_serializing_if` in `HashInput`),
   otherwise an upgrade recreates every running app. New `apps.toml`/`state.toml` field (also `AppState`): bump
   `state::SCHEMA_VERSION` and add a step to `SCHEMA_STEPS` (the compiler enforces it, ADR 0023); describe backward
   compatibility (`deny_unknown_fields` vs rollback) in the PR and in the matching guide in `docs/guides/` — for state
   files that is [schema version](../../docs/guides/state-schema.md). Details: [state-and-schema.md](state-and-schema.md).
5. An implementation decision → a new ADR from [`docs/decisions/0000-template.md`](../../docs/decisions/0000-template.md).
   The index table is generated by `scripts/adr.sh index` — do not edit it by hand. The ADR number is a resource
   shared by parallel branches: reserve it early (push + draft PR with an ADR stub) and merge quickly; if a rebase
   reveals a collision, renumber with one command: `scripts/adr.sh renumber OLD NEW`. Run `scripts/adr.sh lint` before
   the PR too (the `docs-lint` job does the same).
6. Title, commits and PR in Conventional Commits (`<type>(<scope>): <summary>`, see above), in English; `Closes #NN`;
   merge = squash after green CI (`check`, `musl`, `nginx-e2e`, `podman-tests`, `smoke-behind`, `smoke-edge`; a change
   only in `docs/`/`*.md`/`.gitignore` does not build — job `changes`).
7. Parallel agent sessions, briefs, labels and the roadmap project:
   [`docs/contributing/agent-workflow.md`](../../docs/contributing/agent-workflow.md) and
   [`docs/contributing/issues-and-project.md`](../../docs/contributing/issues-and-project.md).
8. Run `bash scripts/claude-md-lint.sh` when you touch `CLAUDE.md` or `.claude/rules/`.
